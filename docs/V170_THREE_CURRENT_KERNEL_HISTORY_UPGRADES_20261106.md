# CADWorkbench v1.70: three engineering increments — current rebuild provenance

**Status:** development source candidate, not a Windows/MSVC-verified release. The previous verified binary must remain the shipping baseline.

## 1. Kernel-proven descendants through fillets and chamfers

`rebuildShapeFeatureTree` can optionally provide the actual `BRepBuilderAPI_MakeShape` builder that generated a **single** selected-edge or all-edge fillet/chamfer. The mixed-history replay retains it until the end of the current rebuild transaction. Subsequent linked modifiers can consult `Modified`, `Generated`, `IsDeleted`, and exact retained subshapes. Any proposed descendant must also exist in the actual new result and pass a unique witness-resolution test.

This is a substantial extension beyond the previous exact-`IsSame`-only rule. A consumed or geometrically ambiguous edge or face remains an error. It does **not** guarantee a persistent name for a new rounded face, nor for arbitrary splits/merges through any CAD operation. After the transaction, the builder is discarded rather than serialized.

## 2. Recorded provenance through manufacturing cuts and additive loft/sweep

The same current-transaction builder mechanism now covers:

* `Cylinder cut X`, `Cylinder cut Y`, `Cylinder cut Z` using their actual cut builder.
* `Loft rectangles` and `Sweep circle path` using the **final additive fuse builder**.

This permits a pre-existing source face or edge to be retargeted through a supported cut or additive form where OCCT confirms its descendant and the saved witness survives. It does not establish ancestry from the frozen base to **newly generated** loft or sweep faces. That separate case is handled by the next feature.

The builder must produce exactly the result shape being evaluated; recorded history from a stale or different builder is rejected. The optional history-output API intentionally only accepts a single shape-feature stage. Branches still require every ancestry route to agree on the resulting descriptor.

## 3. Witnessed references on an intermediate result

The mixed-history editor now permits a face/edge feature's `referenceSourceId` to **equal** its explicitly selected first parent. This represents a witness captured on that intermediate result, for example a planar top face generated by a loft. The reference is re-resolved against that freshly evaluated intermediate result on every rebuild.

Supported choices include witnessed selected edges, planar face machining, and curved shell openings. Matching is fail-closed: deleted/missing, multiply matching or geometrically remote witnesses are rejected. Planar machining keeps its saved world-space design location where still on the resulting face plane, rather than blindly moving with the new face centroid. Nested pattern selections cannot be combined with a direct-stage reference because no ancestry steps are traversed.

This adds a real route to attaching a downstream pocket or shell to intermediate generated geometry, but should **not** be mistaken for universal stable IDs for generated loft/sweep surface patches. Changing the loft shape or guide significantly can require reselection. No new persistence field or schema version is required: `reference_source` continues to store a stable stage ID.
